Small local footprint

The active JARVIS path hosts no speech model or generative LLM. Speech recognition is provided by the ChatGPT app; decision inference is hosted by TypeSafe.

A replaceable input boundary

Dictation is connected through the focused text field and keyboard events. No OpenAI API is integrated into this prototype.

Bounded behavior today

Single app-opening commands for Chrome and Notepad. Search, multi-step tasks, and worker-agent delegation are future work.

Explicit request lifecycle
One command, end to end
1
Receive the global shortcut

RegisterHotKey → WM_HOTKEY
Show the popup, focus its text field, and wait for physical keys to be released.

2
Coordinate desktop dictation

SendInput(Ctrl + I)
First JARVIS shortcut starts dictation; the second sends the same toggle to stop it.

3
Capture the first text-change event

Tkinter <<Modified>> → after_idle
Snapshot non-empty text after stop. Submit once per request, without a fixed completion timer.

4
Ask Jev asynchronously

POST /v1/systemone · HTTPS
Send text plus action/target choices. A background thread returns the decision to the UI event queue.

5
Check and execute once

Reject edited, cancelled, duplicate, or unsupported requests. Log authorization, then launch the fixed application path.

The action contract

Model output is a bounded choice.

Text: “Open Google Chrome.” Action: OPEN_APP Target: CHROME ↓ local checks Launch: approved Chrome executable

Response schema and probability values are validated. There is currently no calibrated minimum-confidence threshold.

Local authority

Execution stays on the PC.

Exact supported phraseAction + target agreementUnchanged request revisionOnce per requestEsc cancellationLog before launch

Keys are saved with Windows user-bound DPAPI encryption and decrypted in memory. A local copy of submitted text and outcome events is retained in an ignored folder. JARVIS does not save audio.

Current input assumption

Observed dictations arrived in one visible update. The first text change is used as a practical trigger, not a guaranteed end-of-dictation signal. Later edits block a pending launch; edits after launch cannot undo it. Windows CompositionFinalized was not observed in the diagnostic trials.

Automated checks use simulated API/launch behavior; live logs and the user-recorded demo provide separate integration evidence. A repeated “Open, open…” phrase was blocked by the local phrase gate, despite Jev choosing Chrome. This is a narrow prototype, not a general voice-agent benchmark.

Next architecture, not implemented

Voice input → task coordinator → specialized workers → verified results → human review when needed.

The present contribution is a working input-to-action bridge with visible execution boundaries. The speech model and audio-processing location inside the ChatGPT desktop app were not independently inspected.
